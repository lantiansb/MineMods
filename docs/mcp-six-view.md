# MCP 六视图

MCP 模式的六视图由外部 Agent 完成。用户在模型卡片点击“复制六视图任务”，发给当前外部 Agent。任务包含当前模型说明、已有部件要求、六个视角的位置与比例，以及 MCP 回传方法。

- 外部 Agent 有可调用的生图工具：直接生成整张六视图，调用 `finish_six_view`，图片自动保存到当前模型，打开的卡片自动更新。
- 外部 Agent 没有生图能力：调用同一工具回报 `unsupported` 和真实原因，卡片显示“不具备生图能力，请独立准备六视图”。

用户生成图片后手动搬运不是 MCP 主流程。独立准备的图片仍可通过现有拖入、粘贴或选择文件入口添加。API 模式保留 Studio 自己调用绘图接口的入口。

## 交互约束

用户于 2026-10-30 明确否定 MCP 下仍强制配置 Studio 绘图 API 的做法，进一步明确由外部 Agent 判断能力、自动回传图片或报告缺少能力。此规则用于六视图的模型卡片、制作过程及模型编辑入口，不扩展为取消 API 模式。

页面主动作是“复制六视图任务”，复制成功只表示任务文字已在剪贴板，不宣称已唤醒或派发给外部 Agent。结果显示来自真实 MCP 提交；没有模拟进度。复制失败时显示可手动复制的完整任务文字。

制作锁定或已有人工六视图时，复制入口会说明原因并禁用，避免外部 Agent 生图后才无法写入。自动刷新只在参考图发生变化时同步图片布局，不覆盖用户正在选择的整图/分图方式。

## 协议

- `get_six_view_prompt({projectId, itemId, note?})`：只读当前模型及最近保存的部件说明，不调用生图接口，也不恢复或修改制作任务。
- `finish_six_view({projectId, itemId, result})`：`generated` 带一张 PNG、JPEG 或 WebP 的 data URL，解码后不超过 4 MiB；`unsupported` 带真实原因。
- MCP 回执仅含状态、说明及图片元数据，不重复返回整张图片的 base64；界面从已有参考图接口读取实际图片。
- 生成图保存为当前模型的 `three_view` / `sheet` / `by: ai`，不能覆盖用户独立提供的六视图。工具拒绝任意文件路径、远端下载地址、非图片和过大数据。
- 外部 Agent 必须真实调用自己的绘图能力，不用程序占位图、SVG 或文字冒充生成结果；本次任务不会自动开始建模。
