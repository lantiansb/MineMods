# 史诗档：超巨型生物、飞行与习性（第三步）

依据：本人 10-12 的要求——「超多细节、超巨型 Boss / 超巨型生物，是一个最终考验，要能做到完整流畅的飞行等各类动作、流畅精美的体型、合理的关节、完整的生物习性，像之前宣传片里的龙一样」；这一档的制作和验收都允许用 GPT 6 Astra 的最高推理档，建议制作模型亲力亲为。

这一档在四个档位（简单 / 标准 / 精细 / Boss）之上加第五档「史诗」，并给所有生物（不只是史诗档）新开两样数据：**飞行（flight）** 和 **习性（habits）**。原则同 Boss 运行时：全部是数据，AI 填参数，Studio 生成 Java；每一项有上限；不改地形。

## 一、档位「史诗」（epic）

| 项 | 史诗 |
|---|---|
| 什么时候用 | 用户要的是整个模组的终极生物：超巨型、超多细节、整场被盯着看，要飞、要有自己的习性（「像宣传片里的龙」「最终考验」「超巨型」「史诗级」） |
| 几何预算 | `epic`：1024 个方块、192 根骨骼、贴图 512、**32 个动作**、每轨 60 帧、整个模型 40,000 帧、同屏 1 只 |
| 必须的动作 | idle、walk、hurt、death；近身打人的 attack；**至少 3 个招式**，每个招式自己的动作；会飞的再加 takeoff、fly、glide（或 hover）、land；有习性的加 rest（休息/睡觉） |
| 碰撞箱 | 必须写 hitbox：身体一个、伸出去的部位（头、尾、翼）各自的箱子 |
| 六视图 | 开工前必须先有（一整张或六张）；没有就先提醒用户给，不「直接开始」 |
| 第一版 | 一次做足：轮廓流畅（圆的地方用 1 像素的 solid）、关节放在骨骼交接处、动作多、不放宽验收 |
| 推荐模型 | 制作和验收都推荐 GPT 6 Astra 最高推理档（MCP 模式下两个窗口的推荐写这个；API 模式写在设置提醒里） |

几何预算的来历：方块、骨骼、贴图、每轨帧数、整个模型的帧数和「最精细」相同（第 9 轮在沙箱里量过能承载）。动作数从 16 放到 32：在开发沙箱里量过，32 个动作、150 根骨骼、共 43,200 个关键帧的文档由脚本交回是 3.0 MB、107 毫秒，低于脚本 4 MB 的输出上限和 2 秒的时限（2026-10-12）。整个模型的帧数不放宽，因为 60,000 帧时同样的文档超过 4 MB 输出上限，被原样退回。

## 二、飞行（flight）

生物文档新字段 `flight`，null 或不写就是不会飞（和以前一样）。

```
flight: null | {
  style: "soar" | "hover",        // soar：大翅膀滑翔型（龙、鹰），要有速度才能留在空中；hover：能悬停（蜜蜂、萤火虫、幽灵）
  speed: 2..30,                   // 巡航速度，格/秒
  altitude: { min: 2..48, max: 4..96 },   // 平时离地高度范围（max > min）
  turn: 20..360,                  // 最快转向，度/秒
  climb: 10..60,                  // 最陡爬升/俯冲角，度
  bank: 0..60,                    // 转弯时机身最多侧倾几度（只是画面）
  air_share: 0..1,                // 没事的时候有多大比例的时间在天上（其余在地上走或休息）
  takeoff: { clip: string|null, seconds: 0.2..5 },
  land: { clip: string|null, seconds: 0.2..5 },
  clips: { fly: string, glide: string|null, hover: string|null }   // soar 要 glide，hover 要 hover
}
```

**玩家看到**：
- 在地上照原样走（idle、walk）。起飞时播 takeoff，几秒内升到 altitude 范围里；在天上扇翅（fly）、平飞或下降时滑翔（glide）、hover 型可以停在空中（hover）；转弯时机身侧倾、爬升俯冲时机身抬头低头；落地时播 land，落稳以后才在地上走。
- 没事的时候按 `air_share` 在天上兜圈、在地上走或休息，不离开家太远（有习性 home 时）。
- 敌对的会飞生物发现目标后在目标上空盘旋，用招式（见下面的俯冲）。
- 不受摔落伤害。

**生成**：
- 飞行状态（GROUND、TAKEOFF、AIR、LANDING）同步给客户端、写进 NBT。
- 天上时 `setNoGravity(true)`，自己的移动控制：朝一个目标点飞，每 tick 按 `turn` 限制转向、按 `climb` 限制俯仰、速度平滑加减（不瞬变）。前方有方块时向上并向侧面避开（前方 3 个距离做射线检查）。没有三维寻路。
- 地上时用原来的地面寻路和 Goal。
- 起飞/落地按状态机计时；落地前先降到离地 1 格以内。
- 客户端：渲染器按插值后的俯仰和侧倾转动整个模型（侧倾 = 转向速度 × 系数，限制在 `bank` 以内）。动作控制器在 AIR 时按速度和竖直速度选 fly / glide / hover。
- Boss 的离开重置（leash）对会飞的生物同样有效：回出生点时飞回去再落地。

**招式的俯冲（dive）**：招式新增可选字段 `dive: boolean`（只有会飞的生物能写 true）和 `where: "ground"|"air"|"any"`（默认 any）。dive 的招式：蓄力时在目标上方拉高、对准；蓄力结束锁定目标当时的位置，以 2 倍巡航速度直线冲过去（受 `climb` 限制的角度以内）；最后一次出手之后拉起回到 altitude。出手判定照原样在出手时刻按每个人当时的位置算。

**限制**：只有 soar/hover 两种；没有三维寻路（复杂洞穴里会卡）；不会在水下飞；不载人。

## 三、习性（habits）

生物文档新字段 `habits`，null 或不写就是以前的样子。

```
habits: null | {
  active: "day" | "night" | "always",           // 不在活动时间就回家休息
  rest: { clip: string|null } | null,            // 休息/睡觉的动作；null：原地不动
  home: { radius: 8..64 } | null,                // 平时不离开出生点（窝）这么远；走远了自己回来
  prey: string[],                                // 原版生物 id（最多 6 个），饿了就去捕猎；空数组：不捕猎
  hunger_seconds: 30..1200,                      // 吃饱以后多久又饿
  eat: { clip: string|null } | null,             // 捕到猎物以后吃的动作
  alert: { clip: string|null, distance: 4..32 } | null   // 玩家第一次走近时的警觉动作（吼、竖起翅膀），之后 30 秒内不再播
}
```

**玩家看到**：白天/夜里按活动时间作息；休息时回窝、播 rest；饿了去追 prey 里的动物，捕到以后播 eat；玩家走近先警觉。敌对生物看到玩家照旧开打（打完回去休息），Boss 的登场优先于 alert。

**生成**：一组 Goal：RestGoal（不在活动时间时回家、停下、播 rest）、ReturnHomeGoal、HuntPreyGoal（饿了时把最近的 prey 设为目标，打死即吃饱）、EatGoal、AlertGoal（同步一个触发动画）。会飞的生物回家、捕猎时飞过去。

**限制**：prey 只能是原版生物；吃不改变血量；作息按世界时间，不看天气。

## 四、对账与验收

- 史诗档：第一节写了「必须」的，缺了就**拦住打包**（不再只是提醒），并写明怎么补：缺 death / attack 动作、招式少于 3 个、没有分部位的碰撞箱（hitbox.parts）、会飞却没有起飞或落地的动作、有习性（不是一直活动）却没有休息的动作。例外只有一条：蓝图或说明的字面里写了「会飞」却没有 flight，是靠字面猜出来的（可能是「不会飞的龙」），只提醒、不拦。「敌对的同时是 Boss」（boss 设置、阶段、晃屏或碎块）第一节的表里没有列为必须，仍然只提醒。精细档和 Boss 档照旧：只提醒、不拦打包（2026-10-12 补充，原先写的是史诗档也不拦）。
- 飞行的 clip、习性的 clip 必须在模型里；不能用 idle、walk、hurt、death。
- 原话要「飞」的生物：有了飞行以后不再列进「这次做不了」。
- 说明书：会飞的生物写「它会飞：在天上……；/tp 它到空中不会掉下来」之类可以亲眼核对的话；习性写作息、回窝、捕猎。
