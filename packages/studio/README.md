# MineMods Studio

MineMods Studio 是一个 Windows 本地 Minecraft 模组创作应用。一个模组对应一个 `.minemods` 工程，工程内可以管理生物、模型、纹理、动画、方块、物品、配方、逻辑、世界观、群系、维度和地形条目。

## 两种连接方式

应用启动后可以在「个人设置」中选择两种工作方式：

- **在这里制作 API**：Studio 直接调用 OpenAI 兼容的模型服务（Responses API 或 Chat Completions），在应用内完成工程构想、内容制作、模型修改和审阅。
- **使用外部模型 MCP**：外部模型客户端通过 Studio 提供的本地 MCP 配置驱动制作，Studio 展示任务、草稿、骨骼模型和保存状态。MCP 模式不会继续调用 Studio 的 API 连接，也不会显示内部制作输入框。

API 向导按「工作方式 → 模型服务 → 连接凭据 → 选择模型 → 验证并连接」逐步进行。OpenAI 官方与 OpenRouter 自动填好服务地址，用户输入 API Key；「其他服务（自己填地址）」需要手填地址和 Key（官方直连或中转都可以）。模型列表来自所选服务，默认使用所选模型完成建模、路由和资产制作，也可在高级设置中指定不同分工。语音转写使用独立的转写模型设置。

只有选择 OpenAI 官方且检测到同源有效配置时，向导才显示「导入检测到的本机配置」；未指定地址时按官方默认地址处理。导入复用已检测凭据，不代表 OAuth 或订阅授权。「其他服务（自己填地址）」和 OpenRouter 不显示导入按钮。用户输入的 API Key 交给主进程使用系统加密保存，已保存密钥不会回传界面，也不进入工程和日志。旧环境变量配置仍兼容，在设置中保存或清除后以本机配置为准。

### 支持哪些模型服务

API 模式面向 OpenAI 兼容的服务，不限于某一家。Studio 先按 Responses API、严格 JSON Schema 和高推理强度发出请求；只有服务明确回答「没有这个接口」（HTTP 404/405/501）或「不支持这个参数」（HTTP 400/422 且错误信息点名了参数）时，才换下一种方式：

1. Responses API，去掉被拒绝的可选参数（如 `reasoning`）。
2. Chat Completions（`<服务地址>/chat/completions`），`response_format` 使用严格 `json_schema`。
3. Chat Completions，`response_format` 使用 `json_object`，JSON Schema 写进系统消息。
4. Chat Completions，不带 `response_format`，只在系统消息里要求返回一个 JSON 对象。

`max_tokens` 被拒绝时改用 `max_completion_tokens`；服务在错误信息里给出上限时按上限重发。密钥无效（401/403）、额度不足（429）、服务故障（5xx）、超时和取消都按原样报错，不会触发换方式。Codex 地址只走 Responses API。

走 Chat Completions 时，Studio 会去掉回复里的 `<think>` 段、代码围栏和前后说明文字再解析 JSON；解析或校验不通过时，把错误发回模型重试一次，仍不通过就报「模型返回的内容未通过完整校验」。Responses API 的严格结构化输出不做这种宽松解析。同一个服务地址和模型试通的方式会记在内存里，应用重启后重新试。

只有官方默认地址加默认模型时，才要求返回的模型名与请求一致。自定义地址或自定义模型名的服务常返回别名、带日期的快照名，或者不返回模型名，这些都接受。

「验证并连接」在 Responses API 或 Chat Completions 任一可用时通过，它只发一条很短的消息，不检查结构化输出。服务没有 `/models` 接口时，向导提示「当前服务没有提供模型列表」，仍可手动填写模型名称。

这些路径用本地模拟服务测试过，没有逐一连接真实厂商验证；不同厂商的错误信息写法不同，遇到未识别的写法时会直接报连接失败。

## 创作与预览

工程构想是父入口。AI 返回的名称、世界观、分类条目和待决定问题先存为审阅稿；用户确认后才建立内容条目。重复导入相同稳定 key 会更新已有条目，并保留模型关联。工程可以保存、重开、交换和导出。

生物内容进入模型构建工作区。内置 Three.js 预览提供真实三维模型、旋转、平移、缩放、部位选择、模型展开、UV 和动画播放；右侧骨骼结构可以折叠和展开。模型支持 `.bbmodel` 导入导出，用户可以用文字继续修改已有模型，修改请求会带上原模型、工程世界观、内容要求和选中部位。确认模型和动画后，进入同一生物的行为与玩法设计。

直接 API 创作使用真实模型请求，并把验证通过的结构化结果写入暂存模型；完整校验和保存成功后才写入新资产。请求失败或取消会保留上一版。MCP 创作使用 `plan_run`、`claim_task`、`update_task`、`commit_task` 和 `module_schema` 等工具，外部客户端提交的草稿和成品会同步到 Studio 的制作现场。MCP bridge 仅监听本机 loopback，并要求客户端使用 Studio 生成的 token；客户端本身需要支持 local stdio MCP。

外部 AI 开工前应调用 `get_capabilities`，核对运行中 Studio 的协议、当前工具与模块清单、执行限制和模型复杂度。返回的契约指纹反映 Schema/模块说明等声明的变化，不是程序二进制摘要。再按 `module_schema` 读取实际字段约束；清单不一致时更新连接并重新加载。没有 `get_capabilities` 的旧连接不能证明最新应用缺少能力。完整复制说明已包含此步骤。

## 模组图鉴：打开别人的模组

在首页「模组图鉴」中选择本地的模组或整合包。打开后默认只有两页：

- 「背包」像打开一个箱子：生物、方块、物品、世界、配方与掉落、动作与声音、模型与贴图各占一个分类，一格一样东西。生物和方块用模型的默认视角截图当图标，物品用贴图。点一格弹出卡片，可以转动模型、播放声音、让 AI 介绍它，并跳到它关联的模型、贴图、动作、声音和出现的群系。内容不超过 8 份的来源会自动放进背包，更大的整合包先让用户挑选。
- 「玩法」是 AI 读完模组后写的介绍。工程还没有分析记录时，打开即自动开始；没有连接 AI 时停在空状态，由用户手动开始。

方块、物品和生物的清单都取自模组自带的数据，不依赖某个模组的写法：方块来自 blockstates，物品来自物品模型，生物来自语言文件、掉落表和刷怪蛋；名字取自模组的语言文件（中文优先，也认 1.12 及更早的 `.lang`）。方块图标用模型贴图画成物品栏里的小方块，不需要原版文件。

生物长什么样由 `mod-core/src/import-entity-models.ts` 找出，结果按工程保存，内容变化时重建：

- **生物和绘制代码的对应**按注册代码的形状读取（实体字段，随后引用一个构造函数，再调用注册），不认具体的加载器接口名，Forge、NeoForge、Fabric 的写法都走同一条路；跟不下去时按类名和文件名与生物 id 匹配，这种结果在卡片上会注明。
- **模型**由 `mod-core/src/imported-java-model.ts` 从字节码还原：把构建模型的指令当数据在一个小解释器上重放，不执行模组代码。游戏类按调用形状识别，所以 Mojang 名、Forge SRG 名、Fabric intermediary 名都能读；1.17 之后的 layer 模型和 1.16 及更早在构造函数里拼部件的模型都支持，循环、分支、辅助方法、拼接出来的部件名也会跟进。GeckoLib 这类模型文件直接使用。
- **原版模型**：模组生物复用原版模型或在原版基础模型上改时，电脑上有对应版本的游戏文件就从中读取；没有时，人形和四足两种基础形状用内置的代替，其余注明原因、不显示图标。
- **贴图**取代码里写的文件名；代码没写全名时用以生物或模型名开头的贴图，并在卡片上注明。模组同时带新旧两套模型时，选与贴图尺寸相符的那套。

整合包里选中的每个模组 JAR 都按同样的方式处理。


关联来自实际归档、JSON 和 Java 字节码。来源路径、SHA-256、证据编号、原始文件编辑、改包（反编译与重新打包）和扫描信息都收在右上角的「高级」里，默认不显示。程序动画、贴图帧动画和独立动画文件分别标注；静态程序动画入口尚未恢复为可播放时间轴。

「让 AI 讲讲它」使用结构化提示词、受限子图与 JSON Schema，结果经过工程快照、条目覆盖、关系状态和证据归属检查。API 模式执行模型请求，MCP 模式等待外部客户端领取并提交；未知关系保留未知。完整修改包、`.modwork`、`.modreverse` 和分类资产工程各有用途，详见 [导入工作流与验证索引](../../docs/import-workflows.md)。

## 界面外观

界面只有一套外观，按 Minecraft 的物品栏窗口来做：浅灰带斜边的窗口、深色格子、石头按钮、黑底输入框和紫边提示框，没有圆角和柔和阴影。全部文字使用随应用打包的像素字体 MineMods Pixel（见 `src/renderer/assets/fonts/`）。

颜色变量在 `src/renderer/themes.css`，窗口、格子、按钮等结构在 `src/renderer/skin.css`，其中 `.mc-window`、`.mc-slot`、`.mc-tooltip`、`.mc-well` 可以在任何功能里直接使用；三维视窗颜色从同一组 CSS 变量读取。旧版设置里保存的主题名会统一迁移为 `craft`。

工程内所有内容在左侧一棵树里按生物、方块、物品、配方、世界、玩法、施法动作分组；可构建的资产与设计稿放在同一组，设计稿带「设计稿」标记。构建、试玩和导出都在标题栏「构建并试玩」打开的面板里。

## 启动与开发

从仓库根目录启动开发预览：

```powershell
bun install
bun run dev
```

源码预览需要先安装 Bun。若需要 Windows 目录包，在 `packages/studio` 内运行：

```powershell
bun run package
```

产物为 `packages/studio/release/win-unpacked/MineMods Studio.exe`，分发或运行时请保留完整的 `win-unpacked` 文件夹。

在 `packages/studio` 内运行检查：

```powershell
bun typecheck
bun run test
bun run build
```

E2E 使用隐藏 Electron 窗口、隔离 profile 和本地 HTTP/SSE fixture，不会调用付费云 API。MCP E2E 使用本地 stdio 客户端和 MCP SDK。需要复测目录包时设置 `STUDIO_PACKAGED_EXECUTABLE` 为完整 EXE 路径，不要只复制 EXE 文件。

导入资产与媒体的定向 E2E 在同一包目录执行 `bun run test:import-assets`。

## 能力边界

本地 fixture 可以验证请求路由、模型列表、Responses 状态、加密持久化、主题、模型预览、工程状态和 MCP 工具链，但不能证明真实云端模型的美术质量、第三方服务持续可用、世界内生成与玩法、账号配额或最终打包版在所有机器上的表现。Minecraft Java 1.21.1、Fabric Loader 0.17.2、Fabric API 0.116.6+1.21.1、GeckoLib 4.8.3 和 Java 21 是当前构建目标；自由创作条目和审阅稿仍属于设计数据，未承诺全部自动编译成游戏玩法代码。

玩家手势（资产种类「手势」）会编译进模组，但今天只做到这里：只能按键播放（G、H、J、K、R、V、B、N 里每键一个），技能触发还没有做；第一人称只有一只纯色的方块右手，播放期间原版手臂和手持物品暂时隐藏；第三人称只转动头、躯干、双臂、双腿；不带物品、粒子、音效或伤害。已知的未知：和其他改写第一人称画面的模组（例如 First Person Model）一起装是否正常，没有验证过。产品代码里的手势目前只通过了编译和单元测试，游戏内效果要等 [一次冒烟检查](../../docs/superpowers/plans/2026-10-05-gesture-smoke.md) 的结果；数据格式、固定与可编辑的部分见 [手势设计说明](../../docs/superpowers/specs/2026-10-05-gesture-design.md)。
